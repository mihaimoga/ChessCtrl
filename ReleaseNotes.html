History

  • Version 1.01 (May 17th, 2026): The first official release of the ChessCtrl demo application marks an important milestone in the development of the project. This initial version showcases the core functionality of ChessCtrl, providing users with a working demonstration of its primary features, user interface, and overall design concept. It represents the transition from prototype to a more polished and structured application, offering a solid foundation for future enhancements, optimizations, and expanded capabilities.
  • Version 1.02 (October 17th, 2026):
    • Fix version string formatting for single-digit minor versions.
    • Added SECURITY.md with security policy and vulnerability reporting guidelines.
    • Added Doxygen documentation comments to ChessDemoDlg.
    • Added inline comments to ChessDemoDlg for UI wiring and thread shutdown logic.
    • Added repository guidance for coding agents (AGENTS.md).
    • Updated the embedded web browser (Microsoft Edge).
    • Removed compiled Release binaries from repository tracking.
  • Version 1.03 (November 14th, 2026):
    • Optimized the computer player (ComputerThreadProc): a computer move now takes about 0.1 to 0.2 ms instead of about 200 to 270 ms (roughly 1,600 to 1,900 times faster in Release x64 benchmarks), and it chooses the same moves as before, except for the fix below.
    • Removed the exceptions the piece rules used to detect empty squares (std::map::at() replaced by find() in Piece and Pawn), passed square names by reference, and merged the duplicated White and Black searches into one shared search that no longer copies the board for moves that cannot be selected.
    • Fixed the game getting stuck when the computer chose a move that left its own king in check (for example capturing a pinned piece or not answering a check): the move was refused, the computer did not move and the game stayed on its turn. The computer now always plays a legal move when it has one.
    • Fixed a memory leak in ChessBoard::submitMove: the copy of the board used to test a move, and the piece captured in it, were not freed when the move was refused because it left the king in check.
    • Added the ChessUnittests project with 129 unit tests (Microsoft Native C++ Unit Test Framework) for the piece rules, the game rules (turns, check, checkmate, stalemate), the memory management of the board, and the computer player.
    • Added the ChessBench project, a console benchmark and equivalence harness for ComputerThreadProc; both new projects are part of the solution.
    • Updated AGENTS.md with the new projects, the build and test commands, and the benchmark procedure.
  • Version 1.04 (November 21st, 2026):
    • Stronger computer player: the greedy search was replaced by a chess engine (ChessSearch.cpp and ChessSearch.hpp) that works on a compact copy of the board and looks 10 plies ahead (iterative deepening, principal variation search with alpha-beta pruning, transposition table, quiescence search, null-move pruning, late move reductions, check extensions, killer and history move ordering). It evaluates the material, the position of the pieces, the bishop pair, the pawn structure, the rooks on open files and the safety of the kings. ComputerPlayer.cpp keeps its functions and only copies the board of the game to the engine.
    • In matches played from different openings the new computer player won 80 of 80 games against the previous one (40 against each of its two search levels, which played the same moves), and a search depth of 10 won 17, drew 14 and lost 1 of 32 games against a depth of 8.
    • A computer move now takes about 0.2 to 0.3 s on average and less than 0.8 s at most in Release x64 benchmarks, instead of 0.1 to 0.2 ms: this is the price of looking ahead. Every search stops after 2,000,000 positions at most. It counts positions and not time, so the same position always gets the same move, on any computer and in any build, and closing the application still stops the computer at once.
    • The computer does not go round in circles when it is winning: a position that comes again in the line it examines counts as a draw. It also knows how to drive a bare king to the edge of the board, and to the corner of the color of its bishop when it has a bishop and a knight, so it checkmates with two bishops, and in most positions with a bishop and a knight.
    • The rules of the game are unchanged: the rules mode of ChessBench gives the same result as in version 1.03.
    • ChessUnittests now has 187 unit tests (129 before) that also cover the move generator of the new engine against the rules of the game, its evaluation and search, whole games between two computer players, and the copy of the board. The position of the test Black_TakesALegalPieceWhenTheCaptureOfAPinnedPieceIsNotLegal was changed because the stronger search saw that the move it expected loses to a checkmate: a knight now protects the pinned bishop.
    • The ChessBench project builds the new engine as well; its ChessSearch.cpp item is left out when /p:SrcDir points at an older version of the engine that does not have the file.
    • Updated AGENTS.md and README.md with the new engine files, the search limits and the benchmark procedure.
  • Version 1.05 (TBD):
    • Renamed the ChessBench project to Benchmark and moved it from the ChessBench folder to the Benchmark folder (Benchmark.vcxproj, Benchmark.cpp and corpus.txt). The program is now Benchmark.exe; its modes and the benchmark procedure are the same, and the rules, search, thread and game modes give the same hashes, moves and scores as before the rename.
    • Renamed the ChessUnittests project to UnitTests and moved it from the ChessUnittests folder to the UnitTests folder (UnitTests.vcxproj, TestSupport.hpp and the six test files). The tests are now built into UnitTests.dll, and their namespace is UnitTests instead of ChessUnittests, so the fully qualified names of the tests start with UnitTests:: now. The 187 unit tests are unchanged and all of them pass in Debug and Release, for Win32 and x64.
    • The Setup installer project takes Benchmark.exe and UnitTests.dll from the renamed projects, instead of ChessBench.exe and ChessUnittests.dll.
    • The Benchmark and UnitTests projects now build into their own folders, for example Benchmark\x64\Release\Benchmark.exe, UnitTests\x64\Debug\UnitTests.dll and UnitTests\Win32\Release\UnitTests.dll, with the intermediate files in the obj folder below them, and no longer into the output folders of the solution, such as x64\Debug, where only ChessDemo.exe is built now. Benchmark.exe is now run from the Benchmark folder as x64\Release\Benchmark.exe thread corpus.txt 3 10; building it with /p:SrcDir, /p:OutDir and /p:IntDir to measure another version of the engine works as before.
    • Building UnitTests, alone or with the whole solution, now runs its unit tests: a post-build step starts vstest.console.exe on the new UnitTests.dll, the build prints the result of every test, and a failing test fails the build. Test Explorer and vstest.console.exe still run the tests without a build.
    • Added a Roadmap for further development to the help page (ChessCtrl.html) and to README.md: the missing rules of chess, a complete game in the demo application, a stronger and more flexible computer player, and a reusable control with tests and documentation.
    • Updated AGENTS.md, README.md and ChessCtrl.html with the new project names; AGENTS.md also has the new folders, the installer project, the namespace of the tests, the output folders of Benchmark and UnitTests, the new path to run Benchmark.exe, and the post-build step of UnitTests. The Roadmap of README.md and ChessCtrl.html no longer says that the tests are run by hand.
