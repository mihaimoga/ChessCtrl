History

  • Version 1.01 (May 17th, 2026): The first official release of the ChessCtrl demo application marks an important milestone in the development of the project. This initial version showcases the core functionality of ChessCtrl, providing users with a working demonstration of its primary features, user interface, and overall design concept. It represents the transition from prototype to a more polished and structured application, offering a solid foundation for future enhancements, optimizations, and expanded capabilities.
  • Version 1.02 (October 17th, 2026):
    • Fix version string formatting for single-digit minor versions.
    • Added SECURITY.md with security policy and vulnerability reporting guidelines.
    • Added Doxygen documentation comments to ChessDemoDlg.
    • Added inline comments to ChessDemoDlg for UI wiring and thread shutdown logic.
    • Added repository guidance for coding agents (AGENTS.md).
    • Updated the embedded web browser (Microsoft Edge).
    • Removed compiled Release binaries from repository tracking.
  • Version 1.03 (November 14th, 2026):
    • Optimized the computer player (ComputerThreadProc): a computer move now takes about 0.1 to 0.2 ms instead of about 200 to 270 ms (roughly 1,600 to 1,900 times faster in Release x64 benchmarks), and it chooses the same moves as before, except for the fix below.
    • Removed the exceptions the piece rules used to detect empty squares (std::map::at() replaced by find() in Piece and Pawn), passed square names by reference, and merged the duplicated White and Black searches into one shared search that no longer copies the board for moves that cannot be selected.
    • Fixed the game getting stuck when the computer chose a move that left its own king in check (for example capturing a pinned piece or not answering a check): the move was refused, the computer did not move and the game stayed on its turn. The computer now always plays a legal move when it has one.
    • Fixed a memory leak in ChessBoard::submitMove: the copy of the board used to test a move, and the piece captured in it, were not freed when the move was refused because it left the king in check.
    • Added the ChessUnittests project with 129 unit tests (Microsoft Native C++ Unit Test Framework) for the piece rules, the game rules (turns, check, checkmate, stalemate), the memory management of the board, and the computer player.
    • Added the ChessBench project, a console benchmark and equivalence harness for ComputerThreadProc; both new projects are part of the solution.
    • Updated AGENTS.md with the new projects, the build and test commands, and the benchmark procedure.
